# Building the Android APK

Plantaloon is an Expo app using Continuous Native Generation: the `android/` folder is
generated by `expo prebuild` from `app.json` and config plugins, and is not committed.
Never edit `android/` by hand — change `app.json` or a plugin in `plugins/` instead.

## One-time setup (Windows)

- **JDK 17+** (for example `C:\Program Files\Java\jdk-21`).
- **Android SDK** in `%LOCALAPPDATA%\Android\Sdk` with: `platform-tools`,
  `platforms;android-36`, `build-tools;36.0.0`, `ndk;27.1.12297006`
  (versions come from `node_modules/react-native/gradle/libs.versions.toml`).
  Install them with the command-line tools' `sdkmanager`; Gradle fetches anything else
  it needs (e.g. CMake) once the Android SDK license is accepted.
- **Release signing key** (see below).

## Signing key — back it up

Release builds are signed with Plantaloon's own key (`plugins/with-release-signing.js`):

- Keystore: `%USERPROFILE%\.plantaloon\plantaloon-release.jks`
- Passwords: `PLANTALOON_RELEASE_*` entries in `%USERPROFILE%\.gradle\gradle.properties`

**Back up both together somewhere safe** (e.g. a password manager or encrypted drive).
Android only installs updates signed with the same key: lose it and every phone must
uninstall Plantaloon (losing its data unless backed up in-app) to install a new build.
Never commit either file.

Without those properties, release builds fall back to React Native's public debug key —
fine for a quick local test, not for phones you'll keep updating.

## Build

```bash
npx expo prebuild --platform android --clean --no-install
cd android
./gradlew.bat assembleRelease -PreactNativeArchitectures=arm64-v8a --no-daemon
```

with `JAVA_HOME` and `ANDROID_HOME` set. Note: `prebuild` rewrites the `android`/`ios` npm
scripts in package.json to `expo run:*`; undo just those two lines (we develop in Expo Go)
rather than `git checkout package.json`, which also drops any uncommitted dependency
changes. Output: `android/app/build/outputs/apk/release/app-release.apk`.

`--no-daemon` matters on Windows: a lingering Gradle daemon keeps files in `android/` locked,
and the next `prebuild --clean` then fails half-way (EBUSY). If that happens, stop the
daemon (`./gradlew.bat --stop`, or end the GradleDaemon java process) and re-run prebuild.

The APK is built for 64-bit ARM only (`plugins/with-arm64-only.js` also drops the other
architectures' prebuilt libraries), which covers practically all phones from the last
several years. Most of its size is the plant photos and the ONNX Runtime library the
scanner uses.

Before each new release, bump `expo.android.versionCode` (and `version`) in `app.json` —
Android refuses to install an update with the same or a lower versionCode.

## Plant scanner

The scanner's model isn't in the APK: the app downloads it once, on request, from the
[plantaloon-scanner](https://github.com/jjroth001/plantaloon-scanner) release and checks
its size and SHA-256. The native code that runs it is `modules/plant-scanner` (Kotlin,
ONNX Runtime). Its species fingerprints (`src/catalog/scan-data.ts`) are made by
`scripts/build-scan-data.py`.

## Checking a build

```bash
apksigner verify --print-certs app-release.apk
aapt2 dump badging app-release.apk
```

The first shows the signing certificate (compare its SHA-256 with the one in the README);
the second shows the package name, version and permissions.

## Installing on a phone

Copy the APK to the phone (USB, a cloud drive, email) and open it; Android asks to allow
installs from that app the first time. Installing over a previous Plantaloon build keeps
its data. The APK is a separate app from Expo Go, so move data across with
Settings › Back up (in Expo Go) and Restore (in the APK).
